- Fallen Below design (current playable code) is described in `docs/archive/GDD_FALLEN_BELOW.md`; status labels DONE/PARTIAL/NOT DONE/BLOCKED only after checks.
- Talk to the owner in Russian. Source strings in code are English; every player-facing string goes through `Loc.t("English text")` (autoload `Loc`, `scripts/autoload/loc.gd`). - Architecture: `run.gd` (root, clock, input) owns `RunState` (RefCounted, all run data + queries) and system Nodes in `scripts/systems/` that get `run` and `s` injected. View (`run_view.gd`) and HUD (`run_hud.gd`) only read state and call run/system methods. All data/balance in `scripts/data/game_data.gd`. Meta progression + save in autoload `Meta`.
- Use `const X = preload(...)` instead of `class_name` to avoid global-class cache issues. Systems must not preload `run.gd` (cycle); keep `var run` untyped.
- Planning: `RunState.time_stopped()` (paused, blocked, or auto-pause while `selected >= 0`/`holding`); `is_blocked()` no longer includes pause, so the player acts while paused. Esc opens `scripts/ui/settings_panel.gd`. Drag & drop in `run_hud.gd` (`_begin/_input/_start_drag`). Lures: `D.LURE_LEVELS`, `s.lure_level`, `s.forecast` via `hero_system.roll_forecast()` (seeded; spawn_party uses it), `Meta.lure_cost()`, building `bait_workshop`. Tests: `tests/ui_test.tscn`, `tests/story_test.tscn`; bot `--loud=0..2`.
- Run HUD layout: top bar (time/attention/controls), right Warden sheet + dungeon levers, hand at bottom; icons from `scripts/ui/icons.gd` (`Icon.make(kind, size)` control in `scripts/ui/icon.gd`); hover text via `hud._hint(control, callable)`. Bot `--hover=x,y` for tooltip screenshots.
- Menus: `UI.background` (animated `backdrop.gd`), `UI.title`, `UI.primary`, `UI.frame`, `UI.hover_tip(self).bind(control, callable)`. Heart drawn by `Icons.heart()` (map, menu, Lair den).
- Sprites: `scripts/ui/art.gd` loads `res://art/<id>.png` if present, otherwise views draw primitives. Asset ids and prompts: `docs/ART.md`.
- Concept (GDD v0.3 "Hungry Dungeon"): the dungeon lures travelers below; the player builds halls and the **Warden** (player's monster, `warden_system.gd`, data in `RunState.warden`) patrols the loop backwards and fights. Warden death ends the run. Travelers escape after 3 laps (raises the Order's attention -> champion). Lures pick traveler types; souls stance devour/raise. Internally travelers are still called "heroes". All 4 acts playable; Act IV Night/Nightfall (`s.night`, `s.nightfall`, `run.nightfall()`, key N / click heart), Archon sunbursts + `s.sanctified`; endings in `scenes/ending.tscn` (`ending_*` stories, true ending needs the full Book). Acts: (`D.ACTS` with per-act `"cards"`, `Meta.selected_act`/`max_act()`, lures/classes with an `"act"` key exist only in that act; Brann's charges and Vael's ignitions in `hero_system.boss_tick`; Act III fire in `fire_system.gd` (`s.fires`, click quenches for Blood); bot `--act=N`, `--noquench=1`, `--shot_night=1`). Fallen Below story: `docs/archive/STORY_FALLEN_BELOW.md`. In-game story text lives in `game_data.gd` (STORY, BEATS, BOSS_LINES, FRAGMENTS, MEMORIES, WHISPERS, ACTS); one-time beats via `run.beat(id)` + `Meta.first_time`; narration via `RunState.narrate` signal; `scenes/story.tscn` plays pages via `Meta.play_story()`.
- Map is procedurally generated each run in `run_state.gd` (`_random_region` → `_trace_ring` → `_commit_loop` + detours).
- Design rule from the owner: no mechanics for the sake of mechanics. Every feature must create a visible player decision tied to the core loop.
- Music: autoload `Music` (`scripts/autoload/music.gd`): `play("menu"|"story"|"run"|"boss")`, `set_intensity()`, `stinger()`. Tracks generated by `tools/music_gen.py` (v2: leitmotif, synthesized ensemble, convolution reverb, seamless loops; `python3 tools/music_gen.py [track]`) into `audio/music/`; `tools/sfx_gen.py` uses `tools/synth_basics.py`. Warden XP/abilities: `D.ABILITIES[warden_id]`, gated by the `pit` building (`Meta.growth_unlocked()`).
- Feedback: `RunState.fx(kind, target, amount)` signal → `run._on_fx` plays `Sfx` (autoload, `audio/sfx/*.ogg` from `tools/sfx_gen.py`) and `run_view.add_fx` (floating numbers, bursts). Emit fx for any new visible event.
- Balance model: `tools/balance_sim.py` (Python, mirrors key numbers from game_data.gd; keep in sync when tuning). Debug keys F1–F5 in `run.gd` (debug builds only).
